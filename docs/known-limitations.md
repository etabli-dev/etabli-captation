# Known limitations and risks

| ID | Limitation or risk | Consequence | Mitigation |
|---|---|---|---|
| L-01 | **iPhone-native calls** cannot be recorded in software. iOS gives apps no access to call audio, and native call recording is unavailable in the EU | Calls taken on the iPhone itself are out of scope for the agent | Record them on mobile hardware (Plaud Note Pro, viaim RecDot, …) and import them (`captation import`) |
| L-02 | **Window titles are unavailable on Wayland** | Browser meetings cannot be told apart from other browser mic use by title | Browsers holding the mic stay category `browser` (audio, or video if the camera is on) |
| L-03 | **macOS may periodically re-confirm screen-recording permission** (ScreenCaptureKit) | Video capture can silently fail until the user confirms | `doctor` checks the permission; QC and warnings flag empty video (to be verified on macOS) |
| L-04 | **Bluetooth or speaker echo** | With speakers, remote voices bleed into the local-mic track; Bluetooth headsets switch to a low-quality call profile while the mic is open (the call itself sounds the same) | Any headset works (wired, USB, Bluetooth, AirPods): the local track follows the microphone the call app uses (`local_input: follow_call`, L-08). For the best quality use a wired or USB headset |
| L-05 | **obs-websocket has no loopback-only bind** | The websocket server is reachable from the LAN unless blocked | Mandatory firewall rule (`exposure_policy: require_firewall`, ADR-012), auth always on |
| L-06 | **Browser helper-process attribution** | The mic may be held by a helper or renderer process whose name differs from the browser | Normalisation to the parent app (`application.name`, parent PID chain) |
| L-07 | **The first seconds of a call are lost** (start debounce + time until the countdown is shown) | The very beginning of a call is not on the recording: about 2–3 s with `record_during_countdown` (ADR-022, default), about 9 s without | Verbal consent must be stated **after** the indicator turns red. The start reminder says so |
| L-08 | **The call app may use a different microphone than the system default** | Wrong or silent local track | macOS: `local_input: follow_call` (default) records the device the call app uses, also after a switch during the call (PF-132). Linux and Windows do not report it yet: there the default input is used; set `recording.audio.local_input` to the device the call apps use; QC raises `qc:local_silent` |
| L-09 | **OBS's own network egress** (updater, opt-in crash-log upload since 32.0) | OBS could contact the internet | Launch with the verified updater-disable flag; `doctor` checks that crash upload is off; end-to-end scenario E10 attributes connections per process |
| L-10 | **Linux distribution support of current OBS**: OBS 33 dropped Ubuntu 24.04 | Native OBS 33 packages may be missing on older distros | Use Ubuntu 26.04 or the Flatpak (ADR-006) |
| L-11 | **Mobile devices**: vendor cloud sync and AI features (Plaud, viaim) can upload study data | Data leaves the controlled environment | Keep vendor cloud and AI off for study data; import local exports only (`docs/import-devices.md`) |
| L-12 | **Late joiners in group meetings** are not covered by prior consent, and the tool cannot detect them | Recording people without consent | Consent workflow (`docs/einwilligung-workflow.md`): late joiners need their own consent or must be excluded; the start reminder names all participants |
| L-13 | **OBS 33 asks for Safe Mode after a crash** (`--disable-shutdown-check` no longer exists, PF-003) and Safe Mode disables WebSockets | After an OBS crash the agent cannot reconnect until someone answers the dialog | Recovery waits 30 s, then finalises the session as `interrupted` and notifies the user (ADR-013) |
| L-14 | **Wayland screen capture needs a one-time portal approval** | Video segments record a black canvas (`capture:not_approved`) until approved | Run `captation obs approve-screen` once (steps below). The restore token is stored and refreshed after every segment. Window targeting is not dynamic on Wayland, so the approved screen is captured (`capture:display_fallback`) |
| L-15 | **Window titles are not read on Linux** (Wayland has none; under GNOME/Mutter even XWayland windows are not listed, so no X11 path is implemented, PF-019) | Browser meetings stay category `browser` | As L-02. An X11 path can be added once verified on an X11 session |
| L-16 | **Flatpak OBS cannot write to the host's `/tmp`** (PF-011) | Recording fails immediately | `data_root` must be outside `/tmp`; the controller refuses `/tmp` with a clear error |
| L-17 | **Camera attribution scans `/proc`** (~35 ms CPU per poll on a busy desktop, PF-017) | Small CPU cost | The scan runs only while an app holds the microphone; camera-only use never starts a recording anyway |
| L-18 | **`data_root` may sit on an unencrypted disk.** The default `~/CaptationData` lies on the home file system, which is often not encrypted (detection: PF-020) | With the default `storage.require_disk_encryption: block`, arming is refused (`disk_encryption_required`); with `warn`, every session gets `storage:disk_unencrypted`. If the encryption state cannot be determined, arming is allowed and sessions get `storage:disk_encryption_unknown` | Set `data_root` to a folder on an encrypted volume (e.g. a LUKS-encrypted data partition, FileVault or BitLocker) and keep the default `block` |
| L-19 | **OBS contacts obsproject.com, Twitch and Amazon IVS at every start** (bundled `rtmp-services` plugin fetches the streaming-service and ingest lists, PF-023) | The machine's IP address is visible to those services when OBS starts; no recording data is sent | Documented in `docs/security.md` and `docs/datenschutz.md`. Accepted and documented (ADR-016). Optional: block outbound traffic of the OBS sandbox at the network level |
| L-20 | **OBS ignores SIGTERM while recording** (it asks for confirmation) and **waits in a Safe Mode dialog after a crash** (PF-022) | After a crash the agent cannot reconnect until someone answers the OBS dialog | The agent finalises the session as `interrupted` after 30 s and shows a notification saying to choose *Run Normally* (ADR-013) |
| L-21 | **macOS: OBS needs Microphone and Screen & System Audio Recording permission** (TCC); macOS may ask again periodically (L-03). Pending PF-127 | Without them the local track or the remote/video tracks stay silent/black | First-run steps below; QC flags silent tracks |
| L-22 | **Windows: unsigned builds trigger SmartScreen** ("Windows protected your PC") on the first start of the installer | One extra click (*More info → Run anyway*) | Code signing (optional, release workflow); details in `docs/runbook-windows.md` §9 |
| L-23 | **macOS/Windows: the tray counts as available once the icon was shown**; an icon hidden in the notification overflow area is not detected | The indicator may sit in the overflow area | Pin the icon (Settings → Personalisation → Taskbar → other icons); checked in the Windows smoke test |
| L-24 | **Windows Firewall does not filter loopback, including connections to the PC's own LAN address** (PF-232) | `obs firewall --check` cannot prove the block locally | Test once from a second device (`Test-NetConnection <pc> -Port 4455` must fail) |
| L-25 | **Browser meetings are identified by the page title only where a title is available.** Windows and macOS read window titles (macOS needs the Screen Recording permission); on Linux under Wayland only Firefox-family browsers report the capturing tab's title (PF-026), Chromium-family browsers (Chrome, Chromium, Edge, Brave, Vivaldi) report none (PF-019) | A Teams, BBB or Cisco Meeting Server call in Chrome on Linux is recorded as `browser` (video, ADR-018) instead of `teams_web`/`bbb`/`cisco_meeting_web` | The recording itself is complete; only the app ID is generic. Use Firefox for meeting pages on Linux if the app ID matters |
| L-26 | **Many in-call pages carry no service name** (Google Meet shows the calendar event, the Zoom web client the topic, a Teams pop-out the meeting name, a BigBlueButton or Jitsi instance may be renamed) | Such pages count as an unidentified browser call | Recorded as video anyway (ADR-018); add the instance's own title with `detection.extra_meeting_titles` |
| L-27 | **Safari captures in `com.apple.WebKit.GPU`**, which other apps embedding WebKit share | A meeting in Safari is recorded as `browser`; another WebKit app using the mic would be too | Countdown and *Cancel* as always; Safari titles are not attributed to the GPU process |
| L-28 | **Windows Phone Link and some Windows apps built on WebView2** (WhatsApp, Teams, Webex) may hold the microphone in a helper whose attribution is not yet confirmed | Detection on Windows may name the app differently or fall back to `unknown` | Unknown apps are recorded (ADR-018); confirmed in the Windows checklist (docs/app-coverage.md) |
| L-29 | **iPhone/iPad cannot run Captation.** iOS call recording (iOS 18.1+) is not available in the EU, so not in Germany, and does not cover WhatsApp, Signal or FaceTime video | Calls taken on the iPhone are not recorded by the software | Take the call on the Mac (FaceTime, Phone app / Continuity: `apple_call`), join FaceTime from a computer browser, or record on mobile hardware and `captation import` |
| L-30 | **Any app that opens the microphone while study mode is on starts a countdown** (`record_unknown_apps: true`, ADR-018), e.g. a dictation tool | An unwanted countdown | Press *Cancel* (the app is then not offered again until it releases the mic), or set `record_unknown_apps: false` |
| L-31 | **macOS: ScreenCaptureKit needs an awake display** (PF-130). While the display sleeps, OBS can start neither the screen capture nor the SCK audio stream | A segment started with the display asleep records a black video and an empty remote track; the local (mic) track is unaffected | Keep the display awake during calls; QC flags the silent remote track. Whether a running capture survives display sleep is open (stage 12) |
| L-32 | **macOS: after an OBS crash, OBS offers to upload the crash report** (opt-in checkbox in the "OBS Studio Crash Detected" dialog, PF-106) | Ticking it sends the report to obsproject.com | Leave "I have read the privacy policy and consent to the upload." unticked; `doctor` warns once an upload has happened |
| L-33 | **macOS, ad-hoc signed builds: every new build asks once for the keychain** (the OBS password; the code signature, and so the keychain ACL, changes with each build) | If OBS already runs when the agent starts, crash recovery connects to it first and the agent waits for that dialog: no menu-bar icon until it is answered | Answer the keychain dialog with *Immer erlauben* once per installed build. A Developer ID signature (ADR-021: when the app is handed to others) keeps the ACL across updates |

## macOS first-run permissions (L-21, pending verification)

1. **OBS → Microphone**: asked when the first `Captation Local` input is created → *Allow*
   (System Settings → Privacy & Security → Microphone → OBS on).
2. **OBS → Screen & System Audio Recording**: asked when the first app-audio or screen input is
   created → enable OBS there; OBS may need a restart (quit it, the agent starts it again).
3. **Établi Captation → Screen Recording** (optional): only for window titles.
4. The agent and `captation-probe` must never cause a Microphone or Camera prompt; OBS is
   started through LaunchServices so macOS attributes the prompts to OBS (PF-103).

## Wayland screen-capture approval (L-14)

`captation obs approve-screen` creates the OBS screen source once; the desktop portal then asks
which screen to share.

- **GNOME:** in the dialog *"Screen Share"*, select the monitor, tick *"Remember this selection"*
  if shown, click *Share*. The screen-sharing indicator appears in the top bar while a video
  segment records.
- **KDE Plasma:** in *"Screen Sharing"*, select the screen, tick *"Allow restoring on future
  sessions"*, click *Share*.

If the dialog is cancelled, video segments keep recording a black canvas with the warning
`capture:not_approved` until the command is run again.
